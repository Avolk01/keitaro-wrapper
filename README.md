# Keitaro Campaign Studio

Тестовое задание: создание кампании с двумя потоками и редактор офферов существующей кампании. Backend — FastAPI + SQLAlchemy, frontend — React + Vite.

## Что умеет

- Загружает домены, группы кампаний, источники, офферы и кампании из Keitaro.
- Создаёт кампанию с выбранными доменом, группой и источником. Первый поток (`regular`, позиция 1) принимает выбранную страну и делает HTTP-редирект на Google. Второй (`default`, позиция 2) отправляет остальной трафик на выбранный оффер.
- Добавляет, отключает и восстанавливает офферы в существующем потоке. Удалённый оффер остаётся в списке с кнопкой «Восстановить».
- Сверяет состав потока с локальным снимком и архивом Keitaro. Если оффер удалён из общего списка Keitaro, он отображается в кампании как «Удалён в Keitaro». Кнопка «Восстановить» добавляет восстановление в черновик; при отправке приложение сначала вызывает API восстановления оффера из архива, затем обновляет поток.
- Все правки офферов и закреплений сначала попадают в черновик браузера. Интерфейс показывает состояние «Есть несохранённые изменения», позволяет отменить черновик и отправляет его в Keitaro только после нажатия «Отправить изменения». При ошибке отправки несохранённая часть черновика остаётся на странице. Черновик хранится в памяти вкладки и исчезает при её перезагрузке.
- Кнопка «Обновить офферы» заново загружает список офферов. Если есть несохранённые изменения, черновик сохраняется, а текущие потоки не перезаписываются.
- Кнопка «Закрепить» фиксирует текущую долю оффера. При добавлении и удалении другие незакреплённые офферы делят остаток поровну целыми процентами. Если сохранить закреплённые доли и сумму 100% невозможно, изменение отклоняется с объяснением. При удалении оффера закрепление снимается; восстановление в черновике возвращает его прежнее закрепление.
- Записывает локальную историю изменений, закреплённые доли и увиденные связи потоков с офферами в SQLite через SQLAlchemy. Сами кампании и офферы остаются в Keitaro.

## Запуск

Нужны Python 3.11+ и Node.js 18+.

```powershell
cd backend
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
```

В `backend/.env` укажите `KEITARO_URL` и `KEITARO_API_KEY`. Ключ находится в профиле Keitaro → «API ключи». Не добавляйте `.env` в Git.

```powershell
alembic upgrade head
uvicorn app.main:app --reload
```

В другом терминале:

```powershell
cd frontend
npm install
npm run dev
```

Откройте `http://127.0.0.1:5173`. Backend API и Swagger доступны на `http://127.0.0.1:8000/docs`. Для нового проекта используется SQLite; `DATABASE_URL` можно поменять на PostgreSQL URL, установив соответствующий драйвер.

## Миграции и проверка

```powershell
cd backend
alembic upgrade head
python -m unittest discover -s tests -v
cd ..\frontend
npm test
```

При обновлении уже запущенного проекта выполните `alembic upgrade head` ещё раз: миграция `0002` создаёт таблицу закреплённых долей, `0003` — снимок офферов потоков. При изменении модели: `alembic revision --autogenerate -m "description"`, затем `alembic upgrade head`. Для отката текущей миграции: `alembic downgrade -1`.

Для сборки интерфейса: `cd frontend; npm run build`.

## Особенности API

Keitaro API вызывается только с backend через заголовок `Api-Key`; ключ не попадает в браузер. Создание выполняется тремя запросами, поскольку API не поддерживает атомарную транзакцию между кампанией и потоками. При ошибке создания потока API возвращает ID частично созданной кампании для ручного исправления. Редактор отправляет черновик через `PUT /api/campaigns/{campaign_id}/streams/{stream_id}/draft`; backend проверяет актуальность потока и затем отправляет в `PUT /streams/{id}` весь список офферов, так как Keitaro заменяет его целиком. Восстановление архивного оффера перед обновлением потока — отдельный запрос `POST /offers/{id}/restore`; эти запросы не атомарны. Каждый изменённый поток сохраняется отдельно, поэтому при сбое после первого потока другие остаются в черновике. Закрепления и снимки состава потоков хранятся в локальной базе приложения; при переносе на другой сервер нужно перенести и эту базу. Если оффер был удалён из потока до первого открытия кампании в обёртке и Keitaro больше не отдаёт его связь с потоком, восстановить эту связь из API уже нельзя.

Документация: [полное ТЗ](https://app.notion.com/p/mnovikov/Adrobot-2b01eb78a7bb80a1b188c3a4a1cad55e), [Keitaro Admin API](https://admin-api.docs.keitaro.io/), [авторизация API](https://docs.keitaro.io/en/development/admin-api.html).

## Структура

`backend/app/service.py` — сценарии создания и редактирования; `backend/app/keitaro.py` — HTTP-клиент; `backend/app/db.py` и `backend/migrations` — локальная история; `frontend/src` — React UI.
